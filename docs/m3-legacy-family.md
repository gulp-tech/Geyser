# M3: первое семейство версий вне окна — 1.26.30

Пилот расширения окна вниз: подключаем **Minecraft Bedrock 1.26.30** (протокол `1001`) —
ближайшую версию ниже текущего окна (26.40+). Если этот шаг проходит, следующие семейства
добавляются по той же схеме.

## Что изменено в коде

| Файл | Изменение |
|---|---|
| `compat/CompatProtocols.java` | новый: центральный выключатель `-Dgeyser.compat.disable-legacy-protocols=true`; список «легаси-семейств» (`26_30`), апстримные семейства им не затрагиваются |
| `network/bedrock/GameProtocol.java` | регистрация кодека `Bedrock_v1001` → версия `26.30` (перед 26.40, порядок возрастающий) |
| `network/bedrock/CodecProcessor.java` | **важное изменение**: version-sensitive сериализаторы теперь устанавливаются только если кодек не старше версии, под которую написан сериализатор. Для 26.40+ все условия истинны — поведение апстрима не меняется; для 26.30 не применяем чужие layout'ы (иначе разъедутся поля пакетов) |
| `registry/populator/BlockRegistryPopulator.java` | палитра `26_30` + ремаппер `ICanHasStates` (полный набор даунгрейдов для кастомных блоков) |
| `registry/populator/ItemRegistryPopulator.java` | `PaletteVersion("26_30", 1001, WildernessBoundConverter.itemMappings())` |
| `registry/populator/TagRegistryPopulator.java` | запись тегов предметов для протокола `1001` (файл `item_tags.26_30.json` переиспользуется) |

Данные (скачаны из истории `CloudburstMC/Data` скриптом `tools/compat-gen/fetch_legacy_data.py`):

```
core/src/main/resources/bedrock/block_palette.26_30.nbt        214 766 B
core/src/main/resources/bedrock/runtime_item_states.26_30.json 254 939 B (1 933 предмета)
core/src/main/resources/bedrock/creative_items.26_30.json      435 725 B
core/src/main/resources/bedrock/item_components.26_30.nbt       16 481 B
core/src/main/resources/bedrock/entity_identifiers.26_30.dat     8 844 B
```

## Включение и отключение

По умолчанию **включено**. Полностью вернуть поведение апстрима (без лишних кодеков и палитр):

```bash
java -Dgeyser.compat.disable-legacy-protocols=true -jar paper.jar
```

Отдельно content guard для контента: `-Dgeyser.compat.disable-content-guard=true`.

## Чек-лист проверки на сервере

1. Поставить собранный `Geyser-Spigot.jar`, запустить Purpur, дождаться строки о загрузке.
   **Если сервер не стартует** — почти наверняка отсутствует/не читается один из файлов
   `bedrock/*26_30*`; в логе будет `AssertionError: Unable to load ...`. Пришлите лог.
2. Зайти современным клиентом (26.60+): всё должно работать как раньше — это регрессионная проверка.
3. Зайти клиентом **1.26.30**:
   - должен пройти вход (никакого `Outdated client!`);
   - мир должен отрисоваться, блоки — не «кашей» (значит палитра совпала);
   - инвентарь открывается, предметы на месте (значит `runtime_item_states` и компоненты совпали).
4. Погонять 5–10 минут: движение, ломание/установка блоков, сундук, крафт, смерть/респавн.
5. Прислать `logs/latest.log` (участок от подключения 26.30 до выхода) — по нему видно, на чём
   именно спотыкается клиент, если спотыкается.

## Что ожидаемо может сломаться (и что тогда делаем)

| Симптом | Причина | Действие |
|---|---|---|
| Кик сразу после входа | клиент не принял `StartGame` (палитра/компоненты) | сверить версию данных: возможно, коммит данных не тот; перегенерировать `--protocols 1001` |
| Блоки «кашей»/не те | палитра от другой версии или рассинхрон runtime id | сравнить `block_palette.26_30.nbt` с данными 26.30 из `CloudburstMC/Data` |
| Пустой инвентарь/пропали предметы | компоненты предметов не совпали | заменить `item_components.26_30.nbt` |
| Вылет на сущностях/звуках | контент из 26.40+ | это уже M1-guard: заполнить манифест и включить |
| Ничего не изменилось, всё ещё `Outdated client!` | кодек не зарегистрирован (свойство отключило) | проверить, что не задан `-Dgeyser.compat.disable-legacy-protocols=true` |

## Почему это пилот, а не «готово»

- Проверен только кодек и данные; клиентского теста ещё не было — его делаете вы.
- Не покрыты: сущности/звуки 26.40+ для 26.30-клиента (это контент-гард, M1 — данные в M2),
  ресурспаки под старую версию, точная раскладка отдельных пакетов.
- `entity_identifiers` для 26.30 скачан, но пока не используется: Geyser рассылает единый список.
